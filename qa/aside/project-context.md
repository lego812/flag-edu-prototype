# Flag Edu — 최신 확정 기준

이 문서는 과거 구현 문서보다 우선하는 QA 기대 동작이다. 테스트 대상 화면을 보고 기준을 임의로 변경하지 않는다. 기준 변경은 사용자 결정 → Codex 문서/코드 변경으로만 반영한다.

## 목적과 원칙

교육 기관의 관리자가 코치를 초대하고, 수업별로 코치가 보고서를 남기는 모바일 우선 웹앱/PWA다. Next.js·Vercel·Supabase 기반이다. 기관별 데이터 격리와 작성자 권한을 유지한다. 실사용자 데이터가 없는 개발 환경에서 테스트한다.

- UI는 stoic. 참고의 밝은 회색·흰색·검정 중심, 넉넉한 여백, 제한적인 노랑 강조. 장식/설명보다 간결한 입력과 조회를 우선한다.
- 기능을 먼저 완성하고 사용 흐름을 검증한다. 새 기능·디자인 제안은 개선점이지 확정 명세가 아니다.
- 주요 작업은 별도 브랜치에서 commit/push. main 병합 및 운영 영향 작업은 사용자 승인 후 수행한다.

## 요구사항 ID와 기대 동작

- R01 공통 UI: 홈(`/dashboard`) 좌측 상단 로고, 다른 화면은 같은 위치에 뒤로가기만 표시. 수업·보고서의 목록 보기는 PC/모바일 모두 1열. 날짜/필터는 작은 버튼. 페이지 대기는 화면에 문구 없이 회전 그래픽으로 표시하며 접근성 이름은 허용한다. 모션 감소 설정 준수. 개발 도구 배지는 하단 메뉴 입력을 가로막지 않으며, 개발 컴파일·런타임 오류는 계속 표시한다.
- R02 로그인/권한: 로그아웃 상태로 루트(`/`)에 접근하면 소개 랜딩 없이 로그인 화면으로 바로 이동한다. 로그인 화면은 `이미 비밀번호를 설정한 계정으로 로그인하세요.`를 표시하지 않는다. `비밀번호를 잊으셨나요?` 링크 아래에 `회원가입은 관리자 계정의 이메일 초대로만 가능합니다.`라고 안내한다. 관리자 초대 방식이며 초대 수락 시 사용할 비밀번호를 설정한다. 초대·비밀번호 변경 대기 구성원은 DB에서도 `pending`으로 유지되어 모든 업무 데이터와 RPC에 접근할 수 없고, 비밀번호 설정 성공 후 서버의 신뢰된 경로만 `active`로 전환한다. 대기 구성원 표시 및 메일 재발송을 제공한다. 관리자와 코치의 기능을 구분하고 다른 워크스페이스의 데이터는 접근 불가. 메일 발송은 기본 QA 범위 밖이다.
- R03 수업: 재사용 가능한 수업 기본정보와 실제 수업 일정을 분리한다. 수업 기본정보는 수업명·장소·진행방식·메모를 가지며, 일정 등록은 기존 수업 선택→반복·날짜/시간→확인 순서다. 반복 선택값에 따른 간격·요일·매월 날짜와 시작/종료일·시간은 `얼마나 자주 진행하나요?` 아래에 함께 표시한다. 목록은 시작일·종료일·상태를 한 번에 초기화하고 최신순(기본)/오래된순으로 정렬한다. 목록은 서울 날짜별 흰색 둥근 카드로 묶으며 날짜 제목 아래 수업명·장소는 왼쪽, 상태·시작 시간(또는 시간 미정)은 오른쪽에 표시한다. 같은 날 여러 수업은 구분선으로 나누고 각 행에서 상세로 이동한다. 현재 조회의 정렬·필터·페이지 범위는 유지한다. 캘린더의 선택 날짜 카드는 기존 표현을 유지한다. 캘린더는 월 이동과 전체/예정/취소/완료 필터를 제공하고 오늘을 기본 선택하며, 선택 날짜의 수업만 아래에 표시한다. 첫 진입의 기본 보기는 캘린더이며 전환 버튼은 왼쪽 캘린더·오른쪽 목록 순서다. 사용자가 선택한 보기 방식은 페이지 이동 후에도 유지한다. 종료 시각이 지난 비취소 일정은 DB에서 완료로 갱신한다. 예정은 노랑, 취소는 빨강, 완료는 초록으로 목록·캘린더에 동일 적용한다. 월간 날짜의 표시점은 상태별로 하나씩 묶고 각 점 바로 옆에는 해당 상태의 수업 건수만 표시한다. 완료 2개·취소 1개라면 초록 점 2와 빨간 점 1을 각각 표시한다. 서울 시간 기준 날짜, 시간 미정, 일/주/월 반복과 최대 366건 제한을 유지한다. 수정/취소는 한 건씩이며 임의 일괄 수정은 요구하지 않는다.
- R04 보고서: 기본 읽기 전용이며 작성자와 같은 기관 관리자는 수정 버튼으로 편집한다. 편집 화면에는 `조회로 돌아가기` 버튼을 표시하지 않는다. 상태는 임시저장/제출 두 개다. 불완전한 임시저장을 허용하고 제출 시 필수값을 검증하며, 제출된 내용을 수정 저장하면 draft로 전환한다. 관리자 확인/승인 기능은 삭제된 요구사항이다.
- R05 입력/사진: 인원·개수 등 수량은 휠 선택, 일반 소수 입력은 기존 숫자 필드. 인원 0 보존. 도움말은 가능한 입력의 placeholder로 표현. 사진은 업로드 전에 브라우저에서 빠르게 축소하고, 성공한 첨부를 전체 페이지 새로고침 없이 즉시 작은 가로 썸네일 목록에 반영한다. 화면 폭을 넘으면 좌우 스크롤한다. 편집 화면은 단일 `사진 추가` 입력으로 모바일의 앨범/카메라 선택을 열며 각 사진 삭제를 제공한다. 삭제 확인은 앱 자체 접근성 대화상자를 사용한다. 사진 변경은 별도 저장되고 보고서는 임시저장 상태가 된다. 같은 기관 관리자는 모든 보고서 사진을 관리할 수 있다. 실제 모바일 카메라는 실기기 검증이 필요하다.
- R06 보고서 조회: 보고서 제목으로 수업명을 표시할 수 있으며 작성 메타정보는 이름과 작성일시만 표시한다(접두어·양식 v1·상태 뱃지 없음). 상세는 흰 문서형 영역과 얇은 항목 구분선을 사용하고, 작은 회색 필드명보다 답변을 크고 진하게 표시한다. 사진을 포함한 모든 항목은 보고서가 참조한 양식의 순서를 유지한다. 단일·복수 선택값은 읽기 전용 칩, 숫자·날짜는 간결한 행으로 표시하며 숫자 0·줄바꿈을 보존하고 빈 값은 미입력으로 구분한다. 긴 제목·필드명·답변은 잘리지 않고 줄바꿈한다. 사진은 작은 가로 썸네일에서 앱 내 확대 대화상자로 열며 취소 수업에서도 조회만 가능하다. 닫기·Escape·배경 클릭을 지원하고 키보드 포커스는 대화상자에 머물다가 원래 썸네일로 복귀한다. 상태 필터 없음. 수업명 검색 결과 중 수업 선택 후 조회, 적용 수업명을 날짜 아래 표시. 수업 검색은 최대 30건. 보고서 날짜 필터는 수업 시작일 기준이다.
- R07 양식: 관리자만 양식을 조회·작성·수정·게시·삭제한다. 사용자 화면에서는 내부 버전 번호를 표시하지 않고 하나의 양식을 수정하는 흐름으로 제공하며, `사용 중` 상태를 강하게 강조하고 동작명을 `조회 / 수정`으로 표시한다. 내부 버전은 과거 보고서 구조 보존에만 사용한다. 삭제는 이력을 지우지 않는 비활성화이며 목록과 새 보고서 작성에서 숨긴다. 단일·복수 선택지는 행 단위 추가·삭제 UI로 편집한다. 코치는 현재 게시된 양식과 본인 기존 보고서가 참조하는 과거 양식만 조회할 수 있다.
- R08 내보내기: 관리자는 1~200개 보고서를 PDF/Excel로 생성해 응답에서 즉시 다운로드한다. 새 파일과 생성 이력은 서버 또는 Storage에 보관하지 않는다. 한글·답변·0 값을 보존하고 Excel 답변 문자열을 수식으로 실행하지 않는다. PDF는 보고서가 참조하는 내부 양식의 필드 순서를 사용하고 별도 크기 설정 없이 일반 입력은 표 행, 긴 글은 내용에 따른 자동 높이 행, 사진은 업로드 순서대로 실제 원본을 포함한 1열 행으로 한 장씩 렌더링한다. 제목·필드명·긴 글·사진은 잘리지 않도록 줄바꿈 또는 페이지를 자동 분할한다. 사진 로딩 실패는 해당 행과 첫 페이지 요약으로 알리되 나머지 PDF는 생성한다. PDF 원본 사진 합계는 100MiB까지 허용한다. 일일 정리는 과거 버전에서 저장된 기존 파일만 제거한다.
- R09 안전성: 코치의 관리자 기능, 다른 워크스페이스 접근, 코치의 다른 작성자 보고서·사진 수정, 중복 등록과 동시 수정 덮어쓰기를 차단한다. 같은 워크스페이스 관리자는 모든 수업 기본정보·일정·보고서·사진·구성원을 편집할 수 있다. 취소 수업의 기존 기록을 보존하고 취소 상태의 직접 복구, 새 보고서 생성·제출, 기존 보고서 답변·사진 변경을 UI·API·DB에서 차단한다. 복구가 필요하면 별도 명시적 기능으로만 추가한다. 권한 테스트를 위해 실사용자의 계정을 변경하지 않는다.
- R10 워크스페이스: 서비스 계층은 `워크스페이스 → 수업 → 일정 → 보고서`이며 별도 운영단위는 두지 않는다. 한 계정은 여러 워크스페이스에 참여할 수 있고 역할·상태는 워크스페이스별로 다를 수 있다. 상단에서 현재 워크스페이스를 확인하고 활성 멤버십 사이를 전환한다. 전환하면 수업·일정·보고서·양식·구성원·내보내기 범위가 즉시 바뀌며 이전 워크스페이스 데이터는 섞이지 않는다. 관리자는 새 워크스페이스를 만들면 그 워크스페이스의 관리자가 되고 즉시 전환된다. 이미 가입한 이메일을 구성원으로 추가할 때 Auth 계정을 중복 생성하지 않는다. 현재 워크스페이스 선택은 계정 전체에 적용되며 전환 전 탭의 오래된 쓰기 요청은 DB에서 차단한다. 같은 브라우저의 다른 로그인 탭은 변경 알림 뒤 서버에서 실제 선택을 재확인하고 새 워크스페이스의 홈으로 자동 이동한다. 이전 상세/편집 상태와 미저장 입력은 자동 저장하지 않는다. 알림 API·저장소 미지원/누락 시 탭 활성화·페이지 복원·화면 활성 중 30초 재확인으로 보완하며, 알림 자체나 다른 계정의 이벤트를 권한·워크스페이스 선택 근거로 삼지 않는다.

## 테스트 시 해석

미구현 제안(반복 수업 일괄 수정 등)을 FAIL로 보고하지 않는다. 관찰로 입증된 기준 위반만 BUG 후보로 기록한다. 선호도/새 기능은 IMPROVEMENT로 분리한다. 로그인·사진·실기기·계정 등 전제가 없으면 BLOCKED이며 PASS가 아니다. 권한 테스트는 승인된 전용 계정/데이터 없이는 수행하지 않는다.

통상 화면 이동은 실제 메뉴/링크로 확인하고 이미 도착한 화면은 재로딩 없이 검증한다. 직접 주소 접근·새로고침·강제 탐색 취소는 별도 관찰로 구분한다. 테스트 방식 변경으로 과거 실패를 소급 통과시키지 않으며, 미대응 browser error와 DOM 예외는 각 실행의 실패로 유지한다.

### 2026-10-07 회귀 확인 기준

- 사진 추가·삭제와 답변 저장은 같은 편집 화면의 보고서 리비전을 공유한다. 성공 직후 새로고침 없이 임시저장·제출할 수 있고, 처리 중에는 다른 변경을 시작하지 않는다. 다른 탭이 변경한 리비전은 자동 채택하거나 덮어쓰지 않는다.
- 필터 초기화는 조회 결과뿐 아니라 날짜·상태·정렬 입력값도 초기화한다.
- PWA 서비스워커는 공개 매니페스트·아이콘만 사전 캐시한다. 로그인 HTML·RSC·API·사진·다른 원점 요청은 가로채거나 캐시하지 않는다. 구버전의 앱 소유 캐시만 정리하며 계정·업무 데이터와 다른 캐시는 보존한다. 공개 파일의 네트워크 실패·캐시 미스도 유효한 실패 Response를 반환하고 실제 등록/HTTP 오류는 숨기지 않는다.
- 보고서 작성자 필터는 현재 워크스페이스의 멤버십을 기준으로 한다. 작성자가 다른 워크스페이스를 선택하거나 비활성화되어도 기존 보고서의 작성자로 조회할 수 있다.
- 대기 구성원 활성화 및 마지막 관리자 보호를 우회하는 내부 역할·상태 변경 함수는 인증 클라이언트에서 직접 실행할 수 없다.
- 워크스페이스 상태 확인의 요청·응답 본문이 지연되거나 일시적인 서버 오류를 반환해도 이후 서버 재확인이 영구적으로 막히지 않는다. 실패 응답·시간 초과 자체는 워크스페이스 변경 근거가 아니며 미저장 입력을 지우지 않는다.
