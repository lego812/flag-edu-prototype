# Flag Edu — 최신 확정 기준

이 문서는 과거 구현 문서보다 우선하는 QA 기대 동작이다. 테스트 대상 화면을 보고 기준을 임의로 변경하지 않는다. 기준 변경은 사용자 결정 → Codex 문서/코드 변경으로만 반영한다.

## 목적과 원칙

교육 기관의 관리자가 코치를 초대하고, 수업별로 코치가 보고서를 남기는 모바일 우선 웹앱/PWA다. Next.js·Vercel·Supabase 기반이다. 기관별 데이터 격리와 작성자 권한을 유지한다. 실사용자 데이터가 없는 개발 환경에서 테스트한다.

- UI는 stoic. 참고의 밝은 회색·흰색·검정 중심, 넉넉한 여백, 제한적인 노랑 강조. 장식/설명보다 간결한 입력과 조회를 우선한다.
- 기능을 먼저 완성하고 사용 흐름을 검증한다. 새 기능·디자인 제안은 개선점이지 확정 명세가 아니다.
- 주요 작업은 별도 브랜치에서 commit/push. main 병합 및 운영 영향 작업은 사용자 승인 후 수행한다.

## 요구사항 ID와 기대 동작

- R01 공통 UI: 홈(`/dashboard`) 좌측 상단 로고, 다른 화면은 같은 위치에 뒤로가기만 표시. 수업·보고서의 목록 보기는 PC/모바일 모두 1열. 날짜/필터는 작은 버튼. 페이지 대기는 화면에 문구 없이 회전 그래픽으로 표시하며 접근성 이름은 허용한다. 모션 감소 설정 준수.
- R02 로그인/권한: 로그아웃 상태로 루트(`/`)에 접근하면 소개 랜딩 없이 로그인 화면으로 바로 이동한다. 로그인 화면은 `회원가입은 이메일 초대를 통해서만 가능합니다.`라고 안내한다. 관리자 초대 방식이며 초대 수락 시 사용할 비밀번호를 설정한다. 초대·비밀번호 변경 대기 구성원은 DB에서도 `pending`으로 유지되어 모든 업무 데이터와 RPC에 접근할 수 없고, 비밀번호 설정 성공 후 서버의 신뢰된 경로만 `active`로 전환한다. 대기 구성원 표시 및 메일 재발송을 제공한다. 관리자와 코치의 기능을 구분하고 다른 기관의 데이터는 접근 불가. 메일 발송은 기본 QA 범위 밖이다.
- R03 수업: 재사용 가능한 수업 기본정보와 실제 수업 일정을 분리한다. 수업 기본정보는 수업명·장소·진행방식·메모를 가지며, 일정 등록은 기존 수업 선택→반복·날짜/시간→확인 순서다. 반복 선택값에 따른 간격·요일·매월 날짜와 시작/종료일·시간은 `얼마나 자주 진행하나요?` 아래에 함께 표시한다. 목록은 시작일·종료일·상태를 한 번에 초기화하고 최신순(기본)/오래된순으로 정렬한다. 목록과 캘린더는 같은 카드 표현을 사용한다. 캘린더는 월 이동과 전체/예정/취소/완료 필터를 제공하고 오늘을 기본 선택하며, 선택 날짜의 수업만 아래에 표시한다. 보기 방식은 페이지 이동 후에도 유지한다. 종료 시각이 지난 비취소 일정은 DB에서 완료로 갱신한다. 예정은 노랑, 취소는 빨강, 완료는 초록으로 목록·캘린더에 동일 적용한다. 서울 시간 기준 날짜, 시간 미정, 일/주/월 반복과 최대 366건 제한을 유지한다. 수정/취소는 한 건씩이며 임의 일괄 수정은 요구하지 않는다.
- R04 보고서: 기본 읽기 전용이며 작성자와 같은 기관 관리자는 수정 버튼으로 편집한다. 편집 화면에는 `조회로 돌아가기` 버튼을 표시하지 않는다. 상태는 임시저장/제출 두 개다. 불완전한 임시저장을 허용하고 제출 시 필수값을 검증하며, 제출된 내용을 수정 저장하면 draft로 전환한다. 관리자 확인/승인 기능은 삭제된 요구사항이다.
- R05 입력/사진: 인원·개수 등 수량은 휠 선택, 일반 소수 입력은 기존 숫자 필드. 인원 0 보존. 도움말은 가능한 입력의 placeholder로 표현. 사진은 업로드 전에 브라우저에서 빠르게 축소하고, 성공한 첨부를 전체 페이지 새로고침 없이 즉시 작은 가로 썸네일 목록에 반영한다. 화면 폭을 넘으면 좌우 스크롤한다. 편집 화면은 단일 `사진 추가` 입력으로 모바일의 앨범/카메라 선택을 열며 각 사진 삭제를 제공한다. 삭제 확인은 앱 자체 접근성 대화상자를 사용한다. 사진 변경은 별도 저장되고 보고서는 임시저장 상태가 된다. 같은 기관 관리자는 모든 보고서 사진을 관리할 수 있다. 실제 모바일 카메라는 실기기 검증이 필요하다.
- R06 보고서 조회: 보고서 제목으로 수업명을 표시할 수 있으며 작성 메타정보는 이름과 작성일시만 표시한다(접두어·양식 v1·상태 뱃지 없음). 상태 필터 없음. 수업명 검색 결과 중 수업 선택 후 조회, 적용 수업명을 날짜 아래 표시. 수업 검색은 최대 30건. 보고서 날짜 필터는 수업 시작일 기준이다.
- R07 양식: 관리자만 양식을 조회·작성·수정·게시·삭제한다. 사용자 화면에서는 내부 버전 번호를 표시하지 않고 하나의 양식을 수정하는 흐름으로 제공하며, `사용 중` 상태를 강하게 강조하고 동작명을 `조회 / 수정`으로 표시한다. 내부 버전은 과거 보고서 구조 보존에만 사용한다. 삭제는 이력을 지우지 않는 비활성화이며 목록과 새 보고서 작성에서 숨긴다. 단일·복수 선택지는 행 단위 추가·삭제 UI로 편집한다. 코치는 현재 게시된 양식과 본인 기존 보고서가 참조하는 과거 양식만 조회할 수 있다.
- R08 내보내기: 관리자는 1~200개 보고서를 PDF/Excel로 생성해 응답에서 즉시 다운로드한다. 새 파일과 생성 이력은 서버 또는 Storage에 보관하지 않는다. 한글·답변·0 값을 보존하고 Excel 답변 문자열을 수식으로 실행하지 않는다. PDF는 보고서가 참조하는 내부 양식의 필드 순서를 사용하고 별도 크기 설정 없이 일반 입력은 표 행, 긴 글은 내용에 따른 자동 높이 행, 사진은 업로드 순서대로 실제 원본을 포함한 1열 행으로 한 장씩 렌더링한다. 제목·필드명·긴 글·사진은 잘리지 않도록 줄바꿈 또는 페이지를 자동 분할한다. 사진 로딩 실패는 해당 행과 첫 페이지 요약으로 알리되 나머지 PDF는 생성한다. PDF 원본 사진 합계는 100MiB까지 허용한다. 일일 정리는 과거 버전에서 저장된 기존 파일만 제거한다.
- R09 안전성: 코치의 관리자 기능, 다른 기관 접근, 코치의 다른 작성자 보고서·사진 수정, 중복 등록과 동시 수정 덮어쓰기를 차단한다. 같은 기관 관리자는 모든 수업 기본정보·일정·보고서·사진·구성원을 편집할 수 있다. 취소 수업의 기존 기록을 보존하고 취소 상태의 직접 복구, 새 보고서 생성·제출, 기존 보고서 답변·사진 변경을 UI·API·DB에서 차단한다. 복구가 필요하면 별도 명시적 기능으로만 추가한다. 권한 테스트를 위해 실사용자의 계정을 변경하지 않는다.

## 테스트 시 해석

미구현 제안(반복 수업 일괄 수정 등)을 FAIL로 보고하지 않는다. 관찰로 입증된 기준 위반만 BUG 후보로 기록한다. 선호도/새 기능은 IMPROVEMENT로 분리한다. 로그인·사진·실기기·계정 등 전제가 없으면 BLOCKED이며 PASS가 아니다. 권한 테스트는 승인된 전용 계정/데이터 없이는 수행하지 않는다.
