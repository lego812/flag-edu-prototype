## 분기 설계

`1`은 헤더/UI, `1-a`는 홈, `1-a-A`는 최초 진입, `1-a-B`는 로고 클릭, `1-a-C`는 새로고침이다. 사진은 `5-c-A`를 형식 분기로 두고 `5-c-A-1` JPEG, `5-c-A-2` PNG로 한 단계 더 나눈다.

숫자 기능군: 1 공통 UI / 2 인증·초대 / 3 수업 / 4 보고서 / 5 입력·사진 / 6 조회 / 7 양식 / 8 내보내기 / 9 권한·경합.

표의 말단 ID만 실행/집계한다. 각 케이스는 전제조건·행동·기대 결과를 가진다. 선행 케이스 실패가 종속 케이스의 실행을 막으면 해당 케이스는 BLOCKED이며 실패한 부모/전제 ID를 적는다. 부모가 PASS라고 모든 자식을 PASS로 채우지 않는다. 환경이 없거나 배타적인 상태를 준비하지 못한 경우에도 BLOCKED로 기록한다.

## 실행과 결과

1. 기준 문서와 개발 이력을 갱신한다. 과거 docs보다 최신 기준 문서를 우선한다.
2. `npm run qa:aside -- --dry-run`으로 실제 전달 프롬프트를 확인한다.
3. 앱 실행과 테스트 계정 로그인 후 `npm run qa:aside`로 조회 전용 분기 실행. 쓰기는 사용자 허용 후 `npm run qa:aside -- --scenario workflow --allow-writes`를 실행한다.
4. 실행마다 기준 문서 스냅샷·해시, 선택 시나리오 해시, 케이스, 커버리지 매핑, git commit/dirty 여부가 저장된다. dirty 작업 트리는 커밋만으로 완전히 재현할 수 없으므로 변경 내용을 별도로 확인한다. Aside는 이 기준과 시나리오를 전달받고 JSON 결과를 출력하도록 지시받는다.
5. 실행 종료 시 스크립트가 `results.json`, `coverage.md`, `findings.md`, `codex-handoff.md`를 만든다. `run.json`의 실행 성공과 테스트 관찰 성공은 구분한다.
6. CLI 출력 포맷 때문에 JSON을 읽지 못하면 모든 항목은 NOT_RUN, 형식 오류로 남는다. Aside 최종 응답을 해당 실행 폴더의 `response.txt`로 저장한 후 `npm run qa:review -- <runId> response.txt`로 다시 검증할 수 있다. 값이나 PASS를 임의로 만들어 채우지 않는다.
7. Codex에게 “`artifacts/aside/<runId>/codex-handoff.md`를 읽고 버그 후보를 검증·수정해줘”라고 요청한다. 이는 자동 코드 실행이 아니라 검토 가능한 인계다.
8. Codex는 재현된 결함에만 수정/회귀 테스트를 추가하고 비식별 이력을 남긴다. UX 선호도·새 기능은 개선 제안으로 따로 승인받는다. 코드 테스트 후 같은 분기를 브라우저에서 다시 검사한다.
9. 해당 재검증 실행·증거를 연결해야 VERIFIED가 된다. 권한/환경 때문에 못 돌렸으면 FIXED_PENDING_RETEST로 남긴다. main 병합은 별도 사용자 승인 후 수행한다.

## 커버리지의 의미

- 설계 커버리지: R01~R09에 매핑된 94 말단 케이스가 존재한다는 뜻. 기능 전체 또는 가능한 모든 조합을 완전히 검사했다는 뜻이 아니다.
- 선택 범위: smoke 29 / workflow 43 / manual 22(현재 자동 실행 제외). 한 실행의 분모는 실제 선택한 묶음의 케이스 수다.
- 관찰 커버리지: `(PASS + FAIL) / 선택 케이스`. BLOCKED·NOT_RUN은 검증하지 못한 항목이다.
- 통과 범위: `PASS / 선택 케이스`. 단일 실행 결과를 다른 계정/기기/배포에도 일반화하지 않는다.
- 분기별 집계: results.json의 coverage.branches에서 1, 1-a, 5-c-A 등의 관찰·통과·차단·미실행 수를 확인한다.
- 코드 커버리지: 테스트 파일 매핑은 증거 위치이지 줄/분기 커버리지 백분율이 아니다. 별도의 계측 없이 코드 커버리지 수치를 주장하지 않는다.

Aside 브라우저 실행 결과는 `qa/aside/findings.md`에서 실행 ID와 검토 상태를 확인한다. 초기 dry-run 파일에 있는 NOT_RUN은 준비 상태이며 실패/통과 실측이 아니다. 원본 로그는 Git 제외, 비식별 검토/수정 요약만 버전 관리한다.
