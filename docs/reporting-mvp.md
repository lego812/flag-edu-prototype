# 보고 업무 MVP

아래는 최초 MVP의 이력이다. 현재 기대 동작은 `qa/aside/project-context.md`가 우선한다. 관리자 확인·승인과 보고서 상태 필터는 제거되었으며, 제출 후 임시저장은 draft로 전환한다. 개발 DB에는 003 이후 202609230001까지 적용된 기록이 있다. 아래의 과거 배포 지시를 그대로 실행하지 않는다.

## 구현 범위

- `/templates`: 관리자 전용 템플릿 생성, 초안 편집, 항목·선택지·순서·필수 여부, 미리보기, 게시 및 버전 보존
- `/reports`: 내 보고서 조회, 동적 입력, 임시저장·제출, 수업별 작성자별 중복 방지
- `/reports/[id]`: 작성자 편집, 관리자 열람·확인, 비공개 사진 조회
- `/admin-reports`: 기관 내 보고서의 기간·수업·작성자·상태 필터
- `/exports`: PDF·XLSX 생성, 비공개 저장, 본인의 생성 이력과 재다운로드
- `/members`: 역할·활성 상태 변경, 마지막 활성 관리자 보호
- `/dashboard`: 가까운 수업·내 임시저장 개수·최근 보고서
- `/forgot-password`: 비밀번호 재설정 메일 요청
- 설치용 PNG 아이콘과 Apple 터치 아이콘

## 먼저 필요한 DB 적용

새 기능을 사용하려면 `202609220003_reporting_workflows.sql`을 개발 DB에 적용해야 한다.
이번 구현에서는 원격 DB에 적용하지 않았다. 기존 001·002 적용 여부 및 연결된 프로젝트가
`flag-edu-dev`인지 확인한 후 실행한다. 프로덕션이나 실제 사용자 DB에는 임의 적용하지 않는다.

```sh
npx supabase migration list
npx supabase db push
```

새 마이그레이션은 원자적 템플릿 저장·보고서 저장/제출·확인·구성원 변경 RPC,
사진 개수·경로 검증, 날짜 검증, 내보내기 이력 권한과 비공개 `report-exports` 버킷을 추가한다.
템플릿 직접 쓰기 및 이전 개별 변경 RPC 권한은 회수하여 새 트랜잭션 RPC로만 쓰도록 한다.
사진 업로드는 기존 `report-images` 버킷을 사용한다.

## 기본 동작과 한계

- 게시된 템플릿은 수정하지 않는다. 기존 버전을 열어 저장하면 새 버전이 생성된다.
- 템플릿 최대 50항목, 선택지 최대 50개, 사진 항목당 최대 10장(기본 3장).
- 텍스트는 항목당 20,000자 이하. 필수값은 제출 때 확인하므로 불완전한 초안 저장은 가능하다.
- 제출 후 텍스트 수정은 유효한 제출 상태를 유지하되 관리자 확인을 해제한다.
- 사진 변경은 별도 저장이며 보고서를 초안으로 돌린다. 사진 변경 후 다시 제출해야 한다.
- 취소 수업의 기존 보고서는 조회할 수 있지만 새 생성·제출은 불가능하다.
- 미제출 집계는 이미 생성된 초안만 포함한다. 참여 코치를 지정하지 않으므로 미작성자를 추정하지 않는다.
- 사진은 브라우저에서 최대 변 1,600px JPEG로 변환하며 목표 400KB 이하, 상한 1MiB다.
  브라우저가 해독하지 못하는 HEIC 등은 JPG/PNG로 다시 선택하도록 안내한다.
- 사진 업로드 후 메타데이터 저장 실패 시 파일 정리를 시도한다. 정리까지 실패하면 안내한다.
  장기 고아 파일 정리 작업과 보관 기간은 별도 운영 정책이 필요하다.
- 내보내기는 최대 200보고서, 총 텍스트 200만 자로 제한한다. 수업 선택 목록은 최근 200개다.
- XLSX는 질문별 행 구조, PDF는 한국어 목록형이다. 사진 파일명·첨부 ID를 포함하며 사진 원본은 삽입하지 않는다.
- 생성 파일은 요청 관리자만 접근 가능하며 자동 만료·삭제 정책은 아직 적용하지 않는다.
  서버 강제 종료 시 `processing` 이력이 남을 수 있으므로 재생성을 안내한다.
- SMTP, Site URL/Redirect URL, Vercel 환경변수 설정은 기존 운영 설정을 사용한다.

## 검증

- `npm run lint`, `npm test`, `npm run build`, `npm audit`
- 로컬 PGlite PostgreSQL에서 001~003 마이그레이션 및 RPC/RLS 검증
- 다른 기관·다른 코치의 보고서와 사진 차단, 관리자 권한, 마지막 관리자 보호
- 템플릿 버전 보존, 중복 보고서 방지, 필수값, 취소 수업 제출 차단, 동시 수정 충돌
- 사진 개수 제한과 업로드 실패 처리, 사진 변경 시 재제출
- 실제 XLSX 생성·재읽기와 수식이 아닌 문자열 저장, 한국어 PDF 생성·재읽기·페이지 분할
- 로컬 프로덕션 서버에서 공개 경로/아이콘 응답과 보호된 경로의 로그인 리다이렉트 확인

PGlite 테스트는 Supabase Auth/Storage의 최소 테이블·역할을 구성해 SQL을 검증한다.
실제 Supabase 메일·Storage HTTP 동작이나 다중 연결 경합을 완전히 재현하지는 않는다.
실제 로그인 후 전 과정, Android/iPhone 설치·카메라, PDF 시각 검수 및 배포 환경 검증은 남아 있다.

## 개발 DB 적용 후 확인 순서

1. 관리자로 템플릿 생성 → 미리보기 → 게시
2. 코치로 수업 선택 → 보고서 생성 → 임시저장 → 사진 첨부 → 제출
3. 관리자로 전체 보고서 열람 → 확인
4. 코치 수정 → 확인 해제 확인 → 사진 변경 시 재제출
5. 기간 필터로 PDF·XLSX 생성 → 다운로드와 이력 재다운로드
6. 구성원 비활성화 후 접근 차단 및 다른 기관 계정의 데이터 격리 확인
