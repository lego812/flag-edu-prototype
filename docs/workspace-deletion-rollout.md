# 워크스페이스 삭제 적용

최신 사용자 결정은 먼저 soft delete로 접근을 종료하고, 삭제 후 30일이 지나면 영구 삭제하는 것이다. 후속 적용은 `docs/signup-consent-rollout.md`를 따른다. 제품에서는 삭제로 표시하고 상세 맨 아래의 관리자 전용 버튼에서 현재 이름을 정확히 입력해야 확정한다. UI, server action, DB가 모두 이름을 검사한다. 이름 변경과 동일한 workspace advisory lock 및 organization row lock을 사용하여 변경된 이름으로 잘못 삭제하지 않는다.

`organizations.deleted_at`을 기록하고 해당 워크스페이스의 모든 멤버십을 비활성화하며 미수락 초대를 취소한다. 수업·일정·양식·보고서·답변·첨부와 Auth 계정은 삭제하지 않는다. Storage API 삭제도 호출하지 않는다. 해당 워크스페이스를 선택 중인 모든 회원은 다른 활성 워크스페이스로 이동하거나 무소속 상태로 전환한다. 다른 워크스페이스 멤버십과 역할은 유지한다.

삭제 표시를 membership/current workspace/current role helper와 전환·참여자 조회·이름 변경·나가기·초대 조회/수락 RPC에서 검사한다. 멤버십이나 오래된 초대 상태만 운영자가 다시 활성화해도 삭제된 데이터에 재접근할 수 없다. 계정 상태를 인증 claims로 판단하지 않고 실제 멤버십을 검사한다. 프로필은 기존 index를 이용하는 두 ID 집합의 UNION으로 찾고 UUID 순으로 잠근다. 변경 후 최신 선택 값을 확인하여 동시 다른 워크스페이스 삭제의 fallback도 정리한다.

적용 순서:

1. 기존 삭제 함수/컬럼이 없는지 migration 이력을 확인한다.
2. `20261012081549_workspace_deletion.sql`을 적용하고 migration 버전을 저장소와 맞춘다. 적용만으로 기존 워크스페이스가 삭제되지는 않는다.
3. 사전 빌드 확인 후 사용자 승인된 병합·배포 흐름으로 main을 반영한다.
4. 삭제 확인 UI·관리자/코치 노출·정확한 이름·취소는 인증된 QA 세션에서 확인한다. 실제 브라우저 실행이 환경 CA 때문에 막히면 인증된 HTTP HTML과 UI unit/DB 검증을 구분한다.
5. 운영 DB 쓰기 검증은 tagged QA 계정만 참여한 임시 워크스페이스를 transaction 안에서 만들고 삭제한 뒤 반드시 rollback한다. 기존 실제 워크스페이스를 삭제하지 않는다. 보고서 보존/권한 차단/미수락 초대 취소/회원 선택 fallback을 검사한다.

기존 발급 사진 signed URL은 최대 600초의 원래 유효기간까지 유지될 수 있다. 삭제 후 새 업무 데이터 조회와 새 signed URL 발급은 차단되며, 이미 받은 파일이나 기존 URL의 회수를 보장하지 않는다. 단위 테스트의 Storage는 메타데이터 fixture이며 실제 파일은 삭제/이동하지 않는다.

UI 복원 기능은 제공하지 않는다. 후속 30일 보관 정책에 따라 일일 자동 정리를 수행한다. 정리 시작 전의 복원만 지원한다. 코드 롤백만으로 실제로 삭제 처리한 워크스페이스의 멤버십이 복원되지는 않는다. 운영자가 복원이 필요한 경우 삭제 표시와 명시적인 멤버십/초대/회원 선택 정책을 함께 복원해야 한다.

참여자 권한 변경도 `20261012092729_workspace_member_action_scope.sql`을 적용하여 렌더된 workspace ID에 바인딩한다. workspace ID 없는 기존 공개 RPC를 인증 클라이언트에서 닫아 이전 배포/폼이 자동 전환된 다른 workspace에 변경을 적용하지 못하게 한다. 새 UI 사전 빌드 완료 후 이 보완 migration을 적용하고 main 배포를 확인한다. 새 정상 role/status 변경은 `manage_workspace_member`를 사용한다.
