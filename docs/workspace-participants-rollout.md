# 워크스페이스 참여자 관리 적용

관리 메뉴에서 워크스페이스·참여자와 보고서 관리(전체 보고서, 양식, 다운로드)를 구분한다. 워크스페이스 이름에서 참여자 상세로 이동한다. 코치는 활성 참여자의 이름과 해당 워크스페이스 역할을 조회하고 관리자는 참여 해제된 참여자도 조회한다. 초대·기존 역할/상태 변경은 선택된 워크스페이스의 상세에서 연결한다.

참여자 내보내기는 확인 후 대상 워크스페이스의 멤버십만 inactive로 바꾼다. Auth 계정, 프로필, 작성 보고서와 다른 워크스페이스 멤버십은 보존한다. 대상이 선택 중인 워크스페이스라면 남은 활성 멤버십으로 선택을 옮기며 없으면 무소속 상태로 전환한다. 본인 제외를 금지하고 마지막 관리자를 보호한다. 대상 워크스페이스의 활성 관리자 권한을 서버와 DB에서 각각 검사한다. 전역 profiles RLS를 확장하지 않는다.

사용자의 이번 작업 운영 승인 후 다음 순서로 진행한다.

1. Supabase 프로젝트 `vhlrmudatjcgspwltdix`에 `20261012065304_workspace_participant_directory.sql`을 적용한다. 테이블/기존 데이터/메일 설정 변경은 없으며 제한된 두 RPC를 추가한다.
2. migration 이력이 저장소 파일 버전과 일치하는지 확인한다.
3. PR을 main에 병합하고 Vercel 운영 빌드 성공을 확인한다.
4. 승인된 QA 계정으로 관리자/코치의 상세 조회, 대상별 역할, 모바일 레이아웃, 확인창 열기·취소를 확인한다. 실제 제외 검증은 승인된 전용 데이터에서만 실행한다. 계정·프로필·기존 보고서·다른 멤버십 보존과 제외된 대상의 접근 차단을 각각 확인한다.

코드만 롤백하면 추가된 RPC는 사용되지 않는다. 마이그레이션 적용 자체는 기존 멤버십을 변경하지 않는다. 실제로 제외한 멤버십은 코드 롤백으로 복원되지 않으며, 복원이 필요하면 관리자의 명시적 상태 변경 또는 새 앱 초대로 처리한다.
