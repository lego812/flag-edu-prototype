# 수업 관리

## 구현 범위

- `/classes`: 같은 기관의 수업 목록, 시작일 기준 기간·상태 필터, 20개 단위 페이지 이동
- `/classes/new`: 제목, 장소, 시작·종료 일시, 메모 등록
- `/classes/[id]`: 상세 조회 및 취소 상태 표시
- `/classes/[id]/edit`: 등록자 또는 같은 기관 관리자만 수정
- 취소 확인 후 기존 `cancel_class_session` RPC 호출. 수업과 보고서는 삭제하지 않음

일시 입력과 표시는 한국 시간(Asia/Seoul)을 사용하고 DB에는 UTC로 저장한다.
기본 조회 기간은 오늘부터 30일 뒤까지이며 양 끝 날짜를 포함한다.
수정 시 `updated_at`을 비교해 다른 사용자의 변경을 덮어쓰지 않는다.
취소된 수업도 내용을 수정할 수 있지만 예정 상태로 복구하지는 않는다.
기관·작성자 정보는 로그인한 프로필에서만 가져오며 기존 DB RLS를 함께 사용한다.

보고서 작성은 이번 구현 범위에 포함하지 않는다. 상세 화면에는 템플릿·보고서
기능의 준비 상태만 표시한다. 추가 DB 마이그레이션은 없다.

## 검증

`npm test`, `npm run lint`, `npm run build`로 자동 검증한다.
단위 테스트는 날짜·입력 검증, 수정·취소 권한, 동시 수정 충돌, 취소 확인,
서버 오류 처리를 포함한다. 모의 테스트는 실제 DB RLS 검증을 대체하지 않는다.

### 개발 환경 수동 확인 항목

- [ ] 관리자와 코치로 로그인하여 수업 관리 메뉴와 목록 확인
- [ ] 수업 등록 후 상세 조회, 새로고침 후 저장 내용 확인
- [ ] 기간 양 끝 날짜, 상태 필터, 20개 초과 페이지 이동 확인
- [ ] 등록자·관리자 수정 가능, 다른 코치 수정·취소 불가 확인
- [ ] 다른 기관 계정으로 목록·상세 접근 불가 확인 (DB RLS 포함)
- [ ] 두 탭에서 같은 수업 수정 시 이전 내용으로 덮어쓰기 차단 확인
- [ ] 취소 확인 후 상태 변경 및 기록 보존 확인
- [ ] 모바일 좁은 화면에서 입력 폼과 상세 화면 확인

이번 개발 실행에서는 연결된 브라우저가 없어 위 수동 확인 및 실제 DB 쓰기 검증은
진행하지 않았다. main 병합 전 개발 환경에서 확인한다.
