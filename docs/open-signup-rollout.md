# 이메일 가입·워크스페이스 초대 적용

누구나 `/signup`에서 이름·이메일·비밀번호를 입력하고 메일의 6자리 코드로 가입한다. 인증된 계정은 `/welcome`에서 자신의 워크스페이스를 만들 수 있다. 만든 사람만 새 워크스페이스의 관리자가 된다. 기존 워크스페이스는 관리자에게 이메일로 초대받고 수락해야 참여할 수 있다.

관리자는 이메일만 입력한다. 새 계정과 기존 계정 모두 수락 전 멤버십을 부여하지 않는다. 메일 버튼은 Supabase Auth로 수신 이메일을 인증한 뒤, 인증된 POST 경로에서 해당 초대 한 건을 수락하고 워크스페이스로 이동한다. 처음 초대받은 계정은 비밀번호를 설정한다. 기존 계정의 비밀번호는 변경하지 않는다. 링크 주소를 GET으로 읽는 것만으로는 멤버십을 만들지 않는다.

## 운영 적용 순서

이 변경은 앱 배포 외에 DB 마이그레이션과 두 이메일 템플릿 적용이 필요하다. 저장소의 HTML 파일을 커밋하는 것만으로 Supabase 관리 설정이 바뀌지는 않는다. 기존 서버 환경변수와 Supabase SMTP를 사용하며 별도 메일 공급자는 추가하지 않는다.

1. Supabase Authentication에서 **Allow new users to sign up**과 이메일 로그인을 허용하고 **Confirm email**을 유지한다. Email OTP Length는 **6**으로 설정한다. 2026-10-10 운영 공개 설정 조회는 `disable_signup=false`, `mailer_autoconfirm=false`, `external.email=true`였다. 이는 메일 템플릿 내용이나 실제 발송 성공의 검증은 아니다.
2. Email Templates의 **Confirm signup** 본문에 `supabase/templates/confirmation.html`, 제목에 `Flag Edu 이메일 인증 및 워크스페이스 초대`를 적용한다. 일반 가입에는 `{{ .Token }}` 코드가 표시되고, 초대로 처음 생성된 계정에는 `초대 수락` 버튼이 표시된다.
3. **Magic Link** 본문에 `supabase/templates/magic-link.html`, 제목에 `Flag Edu 워크스페이스 초대`를 적용한다. 기존 계정의 초대는 이 템플릿으로 발송한다. 이 앱에서는 일반 매직 링크 로그인 UI를 제공하지 않는다. 두 템플릿의 버튼은 반드시 `{{ .ConfirmationURL }}`을 사용해 Auth 인증을 먼저 완료한다.
4. Site URL과 Redirect URL에 앱의 정확한 운영 도메인·`/auth/callback`을 허용한다. 이메일의 `next`는 허용된 내부 경로만 사용한다. PKCE 가입 확인 링크는 가입한 브라우저에서 열어야 하며, 다른 기기에서는 6자리 코드 입력을 사용한다. 관리자 발송 초대는 서버의 implicit Auth 링크로 기기가 달라도 수락할 수 있다.
5. 승인된 DB 연결로 `202610100001_open_signup_workspace_invitations.sql`을 적용하고 main에 앱을 배포한다. 이 SQL은 기존 멤버십을 유지하고 대기 구성원을 재발송 가능한 초대로 옮긴다. 즉시 구성원 추가와 비밀번호 설정에 의한 일괄 활성화 RPC는 차단한다. 구버전 앱의 초대 발송은 더 이상 작동하지 않으므로 마이그레이션과 앱 배포를 같은 작업 창에서 진행한다. 되돌릴 때도 구버전 앱의 권한 부여 경로를 다시 허용하면 안 된다.
6. 전용 승인된 메일주소로 코드 수신·재발송·만료, 새/기존 계정 초대 버튼, 다른 이메일 거절, 멤버십 격리와 팝업 전환을 운영에서 재검증한다. 실제 발송·가입·권한 변경은 격리 브라우저 검증과 별도로 기록한다.

내부 초대는 7일 후 만료되며 이메일 Auth 링크는 프로젝트 Email OTP Expiry 설정을 따른다. 재발송은 새 토큰으로 교체해 이전 링크를 무효화한다. 발송 오류는 대기 초대로 남고 접근 권한은 주지 않는다. 수락 재시도는 멤버십을 중복 생성하지 않으며, 나중에 비활성화된 구성원을 오래된 링크로 복원할 수 없다. 비활성 관리자 재초대는 코치로 참여하며 기존 활성 역할은 유지한다.

이전 방식으로 초대만 받은 대기 계정은 관리자가 **초대 수락 대기**에서 새 메일을 보내야 한다. 이전 초대 링크로 비밀번호를 설정하는 것만으로는 어느 워크스페이스도 활성화되지 않는다. 기존 관리자 초대 CLI 대신 앱에서 초대·수락 후 구성원 역할을 변경한다. 최초 관리자는 공개 가입 후 새 워크스페이스를 직접 만들 수 있다.

현재 VM에는 Supabase 프로젝트 관리용 토큰 또는 DB 연결 자격증명이 없으므로 운영 SQL과 템플릿 적용은 검증·실행하지 않았다. 서비스용 Supabase Secret Key는 Auth/REST 권한이며 프로젝트 설정 변경이나 SQL 실행 자격증명을 대신하지 않는다.
